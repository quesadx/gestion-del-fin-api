Create `playwright.config.ts` at the project root with the following exact configuration:

```typescript
import { defineConfig } from '@playwright/test';

export default defineConfig({
  testDir: './tests/e2e',
  fullyParallel: false,
  workers: 1,
  retries: 0,
  timeout: 15_000,
  expect: { timeout: 5_000 },
  use: {
    baseURL: 'http://localhost:3000/api',
    extraHTTPHeaders: { 'Content-Type': 'application/json' },
  },
  webServer: {
    command: 'npx dotenv -e .env.test -- tsx src/index.ts',
    url: 'http://localhost:3000/api/system/time',
    reuseExistingServer: false,
    timeout: 30_000,
    env: {
      NODE_ENV: 'test',
    },
  },
  projects: [
    {
      name: 'setup',
      testMatch: /global\.setup\.ts/,
      teardown: 'teardown',
    },
    {
      name: 'teardown',
      testMatch: /global\.teardown\.ts/,
    },
    {
      name: 'e2e',
      testMatch: '*.spec.ts',
      dependencies: ['setup'],
    },
  ],
});
```

Key design decisions (per research ARCHITECTURE.md):

- `workers: 1` and `fullyParallel: false` → prevents session middleware race conditions on `last_activity` (session.middleware.ts optimistic lock), ensures camp-scoped data doesn't conflict between parallel workers
- `testDir: './tests/e2e'` → matches existing directory structure
- `webServer.command` → uses `dotenv-cli` to load `.env.test`, runs `tsx src/index.ts` (same as `npm run dev` but with test env)
- `webServer.url` → health-check URL is `/api/system/time` (public, no auth needed)
- `reuseExistingServer: false` → always fresh server, no stale state
- Project dependencies pattern → setup runs first (seeds DB + generates tokens), e2e depends on setup, teardown runs last (cleanup)
- `timeout: 15_000` → 15 seconds per test is generous for API tests (~1s average)
- `NODE_ENV: 'test'` in webServer.env → triggers cron job suppression at src/index.ts:92

<threat_model>

## Trust Boundaries

| Boundary                     | Description                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------------- |
| test runner → Express server | Playwright makes HTTP requests to localhost:3000 — same machine, loopback interface   |
| .env.test → filesystem       | Test DB credentials and JWT secret stored on disk                                     |
| test DB ↔ development DB     | Separate PostgreSQL databases on same instance — credential isolation is the boundary |

## STRIDE Threat Register

| Threat ID | Category               | Component                       | Disposition | Mitigation Plan                                                                                                                                                                                                                                                               |
| --------- | ---------------------- | ------------------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-01-01   | Information Disclosure | `.env.test`                     | mitigate    | `.env.test` added to `.gitignore`; `.env.test.example` committed without real credentials. Test JWT secret is a dedicated test-only value, not the production secret.                                                                                                         |
| T-01-02   | Information Disclosure | `tests/e2e/.auth/tokens.json`   | mitigate    | Entire `.auth/` directory added to `.gitignore`. Tokens are regenerated every test run and never committed.                                                                                                                                                                   |
| T-01-03   | Denial of Service      | `globalRateLimit` (MemoryStore) | accept      | For Phase 1, only system/time tests run (~2 requests) — far below the 200 req/15min limit. Rate limiter bypass for test mode deferred to later phases where request counts increase (PITFALLS.md pitfall 4). Accepted for Phase 1 since the risk is negligible at this scale. |
| T-01-04   | Spoofing               | Test JWT tokens                 | mitigate    | `JWT_SECRET` in `.env.test` is a dedicated test-only value (32+ chars). Test tokens will never be valid against the production server because the secrets differ.                                                                                                             |

</threat_model>
